# قائمة الإطلاق — خطوات يجب تنفيذها يدوياً

هذه الخطوات لا يمكن تنفيذها من الكود وحده. نفّذها بهذا الترتيب.

## 1. عاجل: إغلاق دخول الحسابات بكلمات مرور مشتقة (قبل أي شيء)

المستودع **عام**، وكان يوثّق أن كلمة مرور كل حساب هي `Levi-<الرقم>-auth`
ويذكر رقم الأدمن. أي شخص يستطيع حالياً الدخول كأدمن على المشروع الحي.

1. Supabase → Authentication → Providers → **Phone**: فعّله واربط مزوّد SMS
   (Twilio / MessageBird / Vonage) يدعم أرقام اليمن ‎+967.
2. انشر نسخة التطبيق الجديدة (دخول OTP).
3. طبّق الـ migrations (`supabase db push`)، ومنها
   `20260923120500_retire_phone_derived_passwords.sql` التي:
   - تربط كل حساب قديم برقمه (فيدخل OTP إلى نفس الحساب ونفس الدور)،
   - تستبدل كلمات المرور المشتقة بكلمات عشوائية،
   - تُخرج كل الجلسات الحالية.
4. Authentication → Providers → **Email**: عطّل "Allow new users to sign up"
   (التطبيق لا يستخدم التسجيل بالبريد).
5. راجع `admin_activity_logs` و`auth.audit_log_entries` بحثاً عن دخول أدمن مشبوه.

> إن طبّقت الخطوة 3 قبل الخطوة 1 فلن يستطيع أحد الدخول حتى يُفعَّل مزوّد SMS.

## 2. سجل الـ migrations على المشروع الحي

`20260618000000_fresh_replay_baseline_tables.sql` لا يغيّر شيئاً على المشروع الحي
(كل أوامره IF NOT EXISTS)، لكنه أقدم من آخر migration مطبّقة. سجّله كمطبّق بدل دفعه:

```bash
supabase migration repair --status applied 20260618000000
supabase db push
```

## 3. GitHub Actions لا تعمل إطلاقاً

آخر عمليات النشر لم تفشل بسبب الكود: الـ job ينتهي خلال 3 ثوانٍ دون أن يُسند
له أي runner (لا توجد أي خطوة مُنفّذة ولا سجل). راجع:
Settings → Actions → General (هل Actions مفعّلة؟) و Settings → Billing
(حدّ الإنفاق / طريقة الدفع). الكود نفسه يمر محلياً:
`type-check`، `build:web`، فحوص العقود، و14 ملف اختبار قاعدة بيانات.
